# AI Context
- Summary: Five findings from a repo review of city-jump 0.2.0: a failed load empties the graph it was meant to replace, visibility toggles trigger a full city resolve, the three largest render files have no unit coverage, `.nvmrc` and `render.yaml` disagree on the Node major, and a refused autosave write is swallowed.
- Keywords: review, findings, half, destroyed, city, failed, load, rebuild, config, test, hygiene
- Use when: Working on save/load durability, the cost of a UI toggle in `src/app/app.ts`, unit coverage for `src/render/`, or the Node version pinned for CI and the Render deploy.
- Skip when: The work is about redundant computation inside `rebuild()` itself (that is req_005, Done), the save format or `parseCity` validation rules, or gameplay and visual behaviour.

# Needs
- A load that fails half way through destroys the city already on screen. `restoreCity` (`src/sim/save.ts`) clears the plantings and removes every existing segment BEFORE replaying the saved ones, and throws when the current rules refuse a segment or a node reference is missing. `loadCity` (`src/app/app.ts:168`) catches that throw, shows a refusal and returns `false` -- but the graph has already been emptied and the terrain already regenerated by `applyTerrain`. The player sees a refusal message over stale meshes, and the next edit autosaves the emptied graph over what they had.
- Toggling a checkbox pays for a full city resolve. `onBuildings` (`src/app/app.ts:141`) and `onSelectView` (`src/app/app.ts:146`) both call `rebuild()`, which runs `buildableCells` + `buildingParcels` (the app's own comment calls the parcel solve the most expensive step in there), `heightmap.conformToRoads`, and a rebuild of the ground, trees, world grid, roads, streetlights, traffic, signals and buildings -- when the only thing that changed is which meshes are visible.
- The rendering layer is ~3,500 lines with 37 lines of unit tests. `src/render/traffic.ts` (1,039 lines), `roadMesh.ts` (1,031) and `drawTool.ts` (533) are only exercised by the Playwright interaction suite and the visual shot script, both of which now run off the push trigger. The pure geometry inside them -- lane offsets, portal placement, snapping decisions -- is testable the same way `roofPropY` already is in `src/render/buildings.test.ts`, without a Babylon scene.
- The Node version has already drifted between its two sources of truth: `.nvmrc` says 22, `render.yaml` sets `NODE_VERSION` to 20. CI builds on 22, Render deploys on 20.
- `writeAutosave` (`src/ui/saves.ts:43`) returns `void` and swallows a refused localStorage write, unlike `writeSave` which returns a boolean the UI can act on. A full or disabled store means the player silently loses their session resume with nothing on screen saying so.

# Context
- These findings come from a repository review of city-jump at version 0.2.0. The suite is green at the time of the review: 136 vitest tests across 12 files, `tsc` clean, and the three architecture tests passing.
- The layering guarded by `tests/architecture.mjs` (sim must not touch browser globals or Babylon; render must not import app or ui) is sound and must stay intact -- any geometry extracted out of `src/render/` for testing either stays in `src/render/` as a pure exported function or moves into `src/sim/`, never the other way around.
- `req_005_review_findings_redundant_and_quadratic_rebuild_work` (Done) already removed redundant work INSIDE `rebuild()`. This request is about not calling `rebuild()` at all when nothing that it computes has changed, which is a different problem and does not reopen that scope.
- `parseCity` already validates untrusted save text and refuses malformed or future-version saves; the gap is not validation but what happens when a save passes `parseCity` and is then refused by the graph rules mid-replay.

# Acceptance criteria
- AC1: A load that fails part way through leaves the city exactly as it was before the load was attempted -- same graph, same plantings, same terrain, same rendered scene -- with the refusal message shown, and the failure is covered by an automated test that asserts the pre-load state survives.
- AC2: Toggling the buildings checkbox or switching the select view no longer triggers the parcel solve, terrain conformance, or a rebuild of renderers whose input has not changed; the visible result of each toggle is unchanged.
- AC3: The pure geometric decisions currently locked inside `src/render/` are exported as scene-free functions and covered by vitest unit tests, adding meaningful coverage to the largest untested files without introducing a Babylon dependency into the test run.
- AC4: The Node version has exactly one source of truth in the repository, and CI and the Render deploy demonstrably resolve to the same major version.
- AC5: A refused localStorage write during autosave is surfaced to the player rather than silently dropped.
- AC6: The existing layering constraints in `tests/architecture.mjs` still pass, and no existing check's assertions are weakened by this work.
